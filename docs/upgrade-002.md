# 002 升级：动作备注、训练备注与有氧

沿用现有 React / TypeScript / Supabase，没有更换存储或重建历史表。原有力量、饮食、体重、认证和统计功能保留。

## 手动升级步骤

1. 先备份已有数据。在旧应用“设置 → 导出 JSON”留存业务副本；完整可恢复备份使用自己的 Supabase 数据库备份方案。
2. 打开 Supabase 项目 → **SQL Editor** → New query，将 `supabase/migrations/002_notes_and_cardio.sql` 全文粘贴执行 **一次**。不要重跑 001，不要删表。
3. 002 在事务中执行，错误会整体回滚。若编辑器停在中止事务，先 `rollback;`，排查后重试完整脚本。
4. 确认 `exercises.notes`、`cardio_sessions` 表、RLS 策略和新函数已创建。执行 `select public.get_records()->>'schema_version';` 应返回 `2`；SQL Editor 没有个人登录上下文时，不用它检查个人数据内容。脚本已通知 PostgREST 刷新 schema cache。
5. `git pull` → `npm ci` → `npm run build`，按原方式部署。Supabase 两个环境变量不变。
6. 重新打开应用，在手机/电脑使用同一账号验收。

新项目依次执行 001、002。新前端会检查数据库版本，未升级时提示执行 002，不会把未接入的功能伪装成保存成功。原数据库内容不变。

## 数据与关联

- **动作备注**：`exercises.notes`，默认 `''`，上限 4000 字，与动作 UUID 关联、所有日期共享。重命名和归档恢复仍沿用 ID；未提供备注时不会清空旧备注。动作备注修改不接触训练表或组表。
- **力量整体备注**：继续使用 `workouts.notes`，上限 2000 字，改为多行编辑。专区的 `update_training_notes('strength', id, notes, revision)` 只改备注和版本，不删除/重建组。
- **有氧记录**：独立 `cardio_sessions`，直接关联 Auth 用户，不依赖力量记录。字段含 UUID、日期、可选开始时间、运动类型、分钟、距离 km、平均心率 bpm、整体备注、营养调整开关、版本、创建时间。同日可有多条。
- **有氧整体备注**：`cardio_sessions.notes` 进入备注专区。按 `('cardio', id)` 编辑、跳转，同日多次跑步/骑行不混淆。无备注记录不展示，保存空内容只清空备注，不删训练。
- **历史兼容**：旧动作迁移为空备注；旧训练、组、ID、整体备注不变。原力量训练仍为每天一条、多个动作；本次不改变力量会话数量，有氧支持同日多条。
- **安全**：新表 owner RLS；函数均 `security invoker`，禁止匿名调用。整体备注、有氧编辑/删除检查 ID、用户、revision，旧版本不覆盖其他设备更新。
- **读取**：扩展 `get_records()`，同一 SQL 快照返回所有关系行与有氧列表。JSON 仅为接口传输。备份导出自动包含有氧和动作备注。

时间按“录入日期 + 本地钟表时间”保存，不做 UTC 换日；原力量没有时间，不伪造。跑步、骑行、游泳、步行可填 km；椭圆机和其他不填距离。距离/时长完整时才派生配速或速度：跑步/步行 min/km，骑行/游泳 km/h，不重复存储推导值。

## 页面修改

- `WorkoutPage`：选动作、训练内动作中可查看/独立保存长期备注；新建动作可填备注；每日整体备注继续独立保存。
- `ProfilePage`：动作备注管理；保留所有个人参数，补充有氧能耗说明。
- `NotesPage`：日期筛选、倒序列表、完整内容、编辑/清空、按 ID 打开原训练。
- `CardioPage`：独立 CRUD、当天列表、历史与类型筛选、已记录时长/距离统计、能耗假设。
- `Dashboard` / `HistoryPage`：同日力量与有氧一起展示，只有有氧的日期也进入历史。
- `StatsPage`：复用折线图，新增有氧次数、时长和距离趋势，沿用日期范围，可筛选类型。
- `ExerciseNotes` / `CardioSummary` / `NutritionExplanation`：可复用的小组件；数据访问仍集中在 repository。手机导航调整为两行，保留全部入口。

## 营养逻辑与假设

只有力量时结果与旧版相同，没有更换 BMR/宏量营养算法。当前仓库原本以成人维持体重为目标，没有增肌/减脂能量设置，本次没有删除或新增这类目标。

```text
日常基础目标 = 原 BMR × 原日常活动系数
力量净消耗 = (3.5 − 1) × 3.5 × 体重 kg / 200 × 当天力量分钟
每项有氧净消耗 = (对应 MET − 1) × 3.5 × 体重 kg / 200 × 分钟
建议热量 = 日常基础目标 + 力量净消耗 + 全部计入的有氧净消耗
蛋白质 = 原体重参数（默认 1.6 g/kg）
脂肪 = 建议热量 × 原脂肪占比 / 9
碳水 = 剩余热量 / 4（最低 0，沿用原规则）
```

均扣除静息 1 MET，避免与基础能量重复；活动系数不含专门训练，力量时长只填力量部分。如果有氧已包含在日常活动中，或不接受该强度假设，取消该记录的“计入营养调整”，记录仍参与训练统计，不追加热量。

运动参数集中于 `src/domain/cardio.ts`，来源为 [2024 Adult Compendium](https://pacompendium.com/)：

| 类型   | 明确的估算假设       | MET | 代码及来源                                               |
| ------ | -------------------- | --- | -------------------------------------------------------- |
| 跑步   | 一般慢跑、自选配速   | 7.5 | [12020](https://pacompendium.com/running/)               |
| 骑行   | 休闲、低于约 16 km/h | 4.0 | [01010](https://pacompendium.com/bicycling/)             |
| 游泳   | 较慢休闲自由泳       | 5.8 | [18240](https://pacompendium.com/water-activities/)      |
| 椭圆机 | 中等强度             | 5.0 | [02048](https://pacompendium.com/conditioning-exercise/) |
| 步行   | 专门的运动步行       | 3.5 | [17160](https://pacompendium.com/walking/)               |
| 其他   | 强度未知，不估算     | —   | —                                                        |

这些是界面显示的近似强度，不代表实际每次能耗。不用距离或心率猜测强度；缺时长/体重、未知类型不追加；缺个人资料/当日或更早体重则不显示营养建议。时长/距离统计说明有效测量条目数，趋势不画缺失测量的伪零值。不同类型的距离合计只作汇总，建议按同一类型比较。

新增/修改/删除后自动刷新重算；蛋白质逻辑不变，碳水由总热量分配，不是“每分钟有氧加几克碳水”。首页区分日常基础、力量和有氧调整。历史建议仍使用当前个人参数与当时最近体重重新估算，历史实际摄入快照不变。所有结果仅为日常记录参考，非医学建议。
